# WhaleTrade Journal — UI Design Rules

เอกสารนี้กำหนดหน้าตาของแอป: สี ตัวอักษร ระยะห่าง ขนาด component และการปรับตามขนาดหน้าต่าง
ใช้คู่กับ `database.md` (ข้อมูล) และ `requirements.md` (ฟีเจอร์)

- แอปเป็น Electron บน macOS จึงกำหนด responsive ตาม **ความกว้างหน้าต่าง** ไม่ใช่มือถือ
- ทุกค่าในเอกสารนี้ใช้หน่วย px ที่ขนาดหน้าจอ 1x (Figma frame) ให้เขียนเป็น CSS variables ตามหัวข้อ 11 แล้วอ้างอิงจาก token เท่านั้น ห้ามใส่ค่าสี/ระยะตรงๆ ใน component
- ค่าที่มีคำว่า "(ประมาณจากภาพ)" ให้ตรวจกับไฟล์ Figma ก่อนใช้จริง

---

## 1. หลักการ

1. **สงบ อ่านง่าย ไม่เร่งเร้า** แอปเน้นการลงทุนแบบปันผลระยะยาว ห้ามใช้สีแดง/เขียวจัดเป็นพื้นที่ใหญ่ ใช้เป็นสัญญาณเท่านั้น
2. **สีหลักมาจาก palette 9 สีเท่านั้น** สีอื่นที่ใช้ต้องเป็นสีอ่อน/เข้มที่ผสมจาก palette (tint) ตามที่ระบุในหัวข้อ 2.2 ห้ามเพิ่มสีใหม่
3. **ระยะห่างทุกค่าเป็นผลคูณของ 4** (4, 8, 12, 16, 20, 24, 32, 40, 48, 64)
4. **ขอบมนทุกชิ้น** ปุ่มและช่องกรอกเป็นทรงแคปซูล (pill) การ์ดมนใหญ่ ไม่มีมุมเหลี่ยมในแอป
5. **ทำงานออฟไลน์** ฟอนต์ ไอคอน อีโมจิ และภาพประกอบ ต้องติดไปกับแอป ห้ามโหลดจากเว็บตอนใช้งาน

| navy-900 บนขาว / paper / parchment | ~15–17 : 1 | ใช้ได้ทุกขนาด |
| navy-700 บนขาว | ~8 : 1 | ใช้ได้ทุกขนาด |
| ขาว บน navy-900 / navy-700 | 17 : 1 / 8 : 1 | ใช้ได้ทุกขนาด |

| ขาว บน blue-500 | ~3.9 : 1 | ใช้ได้กับข้อความ **semibold ≥ 14px** (ปุ่ม, ชิป) และข้อความ ≥ 18px; ข้อความเนื้อหาบนการ์ด hover ให้เป็นขาว 100% ไม่ลดความทึบ |

**ห้ามสื่อความหมายด้วยสีอย่างเดียว** ยอดบวก/ลบต้องมีเครื่องหมาย `+` / `−` หรือไอคอนกำกับเสมอ

## 3. ตัวอักษร

### 3.1 ฟอนต์
- ภาษาอังกฤษ/ตัวเลข: **Montserrat** (ตามดีไซน์) น้ำหนัก 400 / 500 / 600 / 700
- ภาษาไทย: Montserrat ไม่มีอักษรไทย ให้ต่อด้วย **IBM Plex Sans Thai** (หรือ Noto Sans Thai) น้ำหนักเดียวกัน
- `font-family: "Montserrat", "IBM Plex Sans Thai", system-ui, sans-serif;`
- ทั้งสองฟอนต์เป็นสัญญาอนุญาต OFL ใส่ไฟล์ `.woff2` ไว้ใน `assets/fonts/` แล้วโหลดด้วย `@font-face` (ห้ามโหลด Google Fonts ตอนใช้งาน)
- ตัวเลขเงินและตารางใช้ `font-variant-numeric: tabular-nums;` ให้หลักตรงกัน

### 3.2 ขนาด (font-size / line-height / weight)
| Token | ขนาด | ใช้กับ |
|---|---|---|
| `display` | 40 / 48 / 700 | ตัวเลขผลลัพธ์ใหญ่ ("1,360,000 THB" ใน Your Estimate) |
| `stat` | 30 / 38 / 700 | ตัวเลขสรุปบนการ์ด ("2,000,000", "1,450,000") |
| `h1` | 28 / 36 / 700 | ชื่อหน้า ("Welcome back", "Your Portfolios", "Settings") |
| `h2` | 20 / 28 / 600 | หัวข้อส่วน ("Transaction Logs", "Your Numbers") |
| `h3` | 17 / 24 / 700 | ชื่อการ์ด ("Today Journal", ชื่อพอร์ต) |
| `body` | 14 / 22 / 400 | เนื้อหาทั่วไป, ช่องกรอก, เมนู |
| `body-sm` | 13 / 20 / 400 | ข้อความตัวอย่างบนการ์ด, คำอธิบายใต้หัวข้อ |
| `caption` | 12 / 16 / 500 | วันที่, ป้าย, หน่วย |
| `overline` | 11 / 16 / 600 ตัวพิมพ์ใหญ่ ระยะตัวอักษร 0.08em | ป้ายบนการ์ด ("ANNUAL GOAL", "TOTAL RECORDED DCA") |

- ข้อความภาษาไทยเพิ่ม line-height เป็น **1.6** ของขนาดตัวอักษร (สระบน/ล่างไม่ชนกัน) ทำผ่าน `:lang(th)`
- หน่วย "THB" ต่อท้ายตัวเลขใหญ่ใช้ขนาด 0.5 เท่าของตัวเลข น้ำหนัก 600 สี text-muted
- ความยาวบรรทัดเนื้อหายาว (หน้าเขียนโน้ต) สูงสุด 72 ตัวอักษร (~720px)

## 4. ระยะห่าง ขอบมน เงา

### 4.1 Spacing scale
`--s-1: 4` · `--s-2: 8` · `--s-3: 12` · `--s-4: 16` · `--s-5: 20` · `--s-6: 24` · `--s-8: 32` · `--s-10: 40` · `--s-12: 48` · `--s-16: 64`

| ใช้กับ | ค่า |
|---|---|
| ช่องว่างระหว่างไอคอนกับข้อความ | 8 |
| ระยะในชิป/ป้าย | 4 แนวตั้ง × 10–14 แนวนอน |
| ระยะในการ์ด | 20 (หน้าต่างเล็ก) / 24 (ปกติขึ้นไป) |
| ช่องว่างระหว่างการ์ดในตาราง (grid gap) | 16 / 20 / 24 ตามขนาดหน้าต่าง |
| ระยะระหว่างหัวข้อหน้ากับเนื้อหา | 24 |
| ระยะระหว่างส่วนใหญ่ในหน้า | 32 |
| ระยะขอบหน้า (page padding) | 24 / 32 / 40 ตามขนาดหน้าต่าง |

| Token | ค่า | ใช้กับ |
|---|---|---|
| `--r-sm` | 8 | ป้ายเล็ก, ช่องในปฏิทิน |
| `--r-md` | 12 | เมนู sidebar, textarea, ช่องอีโมจิ, กล่องข้อความแนะนำ |
| `--r-lg` | 16 | การ์ดทุกแบบ, ตาราง |
| `--r-xl` | 20 | sidebar, modal, กล่องตัวเลือกอีโมจิ, การ์ด auth |
| `--r-pill` | 999 | ปุ่ม, ช่องกรอกบรรทัดเดียว, ชิป, ป้าย, แถบความคืบหน้า, สวิตช์ |

## 5. Responsive

### 5.1 ขนาดหน้าต่าง
- `BrowserWindow`: `minWidth: 1024`, `minHeight: 680`, ขนาดเริ่มต้น 1440 × 900
- เนื้อหาหลักกว้างสูงสุด **1440px** จัดกึ่งกลาง (จอใหญ่กว่านี้ไม่ยืดการ์ดจนบาง)

| ช่วง | ความกว้างหน้าต่าง | Sidebar | Page padding | Grid gap |
|---|---|---|---|---|
| Compact | 1024–1279 | แบบไอคอน 76px | 24 | 16 |
| Regular | 1280–1599 | เต็ม 232px | 32 | 20 |
| Wide | ≥ 1600 | เต็ม 232px | 40 | 24 |

- ความสูงหน้าต่าง < 760px: ซ่อนกล่องภาพประกอบใน sidebar (เหลือแถวผู้ใช้)
- ใช้ CSS Grid แบบ `repeat(auto-fill, minmax(<ขั้นต่ำ>, 1fr))` ให้จำนวนคอลัมน์ปรับเองแทนการกำหนดตายตัว
- ตารางที่กว้างกว่าพื้นที่ (Transaction Logs) เลื่อนแนวนอนภายในการ์ด คอลัมน์แรก (ชื่อหุ้น) ติดอยู่ทางซ้าย (`position: sticky`)

### 5.2 การจัดวางแต่ละหน้า (คอลัมน์ Compact / Regular / Wide)
| หน้า | การจัดวาง |
|---|---|
| My Journals | การ์ดโน้ต `minmax(232px, 1fr)` → 3 / 4 / 5 คอลัมน์; หัวหน้า: ชื่อ+คำอธิบายซ้าย, ช่องค้นหา (กว้าง 280) + ปุ่ม New Note ขวา; Compact ช่องค้นหาลงบรรทัดใหม่เต็มความกว้าง |
| Write / Edit Note | คอลัมน์เดียวกว้างสูงสุด 880 กึ่งกลาง: กล่องเลือกอารมณ์ → TITLE → พื้นที่เขียน (parchment, สูงขั้นต่ำ 320) → แถวปุ่ม (Delete ซ้าย, Cancel + Save Changes ขวา) |
| Your Portfolios | การ์ดพอร์ต `minmax(300px, 1fr)` → 2 / 3 / 3–4 คอลัมน์; กล่องข้อความแนะนำ parchment เต็มความกว้างด้านล่าง |
| Portfolio Detail | แถวสถิติ: Goal (2fr) + DCA (1fr) + Yield on Cost (1fr); Compact: Goal เต็มแถว แล้ว DCA + Yield 2 คอลัมน์; Holdings เป็นแถวชิปเลื่อนแนวนอน; ตาราง Transaction เต็มความกว้าง |
| Reminders | 2 คอลัมน์: ปฏิทิน + Scheduled In Day (7fr) / Gentle To-Dos (5fr, ขั้นต่ำ 300); Compact: To-Dos ลงไปอยู่ล่างเต็มความกว้าง |
| Target Calculator | 2 คอลัมน์: ฟอร์ม (1fr) / Sanctuary Summary (กว้าง 320, `position: sticky; top: 24`); Compact: Summary ย้ายขึ้นบนเป็นแถบสรุปแนวนอน; ส่วน Your Estimate เต็มความกว้างทุกขนาด |
| Saved Plans | การ์ดแผน `minmax(280px, 1fr)` → 2 / 3 / 4 คอลัมน์ |
| Settings | คอลัมน์เดียวกว้างสูงสุด 960; ช่อง Display name + Email วาง 2 คอลัมน์ → Compact เหลือ 1 คอลัมน์ |
| Trash | รายการแบบตาราง/การ์ดเดียวกับ Your Portfolios แต่การ์ดเป็นสีจาง (ความทึบ 0.7) พร้อมปุ่ม Restore / Delete forever |

## 6. App shell และ Sidebar

### 6.1 โครงหน้า
```
┌──────────────────────────────────────────────────────┐
│ [Sidebar ลอย]  │ Top bar (สูง 56)                     │
│  margin 16     │──────────────────────────────────────│
│                │ เนื้อหา (scroll เฉพาะส่วนนี้)          │
└──────────────────────────────────────────────────────┘
```
- พื้นหลังหน้าต่าง `--paper`; sidebar เป็นการ์ดขาวลอย ห่างขอบหน้าต่าง 16 ทุกด้าน สูงเต็มหน้าต่าง (ลบ 32)
- Top bar: ซ้ายเป็น breadcrumb/วันที่ (`caption`, text-muted), ขวาเป็นปุ่มกระดิ่ง Notification (ปุ่มไอคอน 36, badge จำนวน) + avatar 32
- เนื้อหาเลื่อนเอง sidebar และ top bar อยู่กับที่

### 6.2 Sidebar แบบเต็ม (Regular / Wide)
| ส่วน | สเปก |
|---|---|
| ตัวกล่อง | กว้าง 232, พื้น `--surface`, มน `--r-xl`, เงา `--shadow-md`, padding 20 แนวตั้ง × 16 แนวนอน, จัดเป็น flex คอลัมน์ |
| โลโก้ | ภาพวาฬ 44 + ข้อความ "Whale Trade Journal" 2 บรรทัด 16/20 น้ำหนัก 700 สี navy-900, ช่องว่าง 10, ระยะล่าง 24 |

## 7. Component

### 7.1 ปุ่ม (ทรงแคปซูลทั้งหมด)

| md | 40 | 20 | 14 / 600 | ปุ่มทั่วไปในแอป |
| lg | 48 | 28 | 15 / 600 | ปุ่มหลักหน้า auth, Calculate, ปุ่มใน modal (เต็มความกว้าง) |

| แบบ | ปกติ | Hover | กด | Disabled |

| Secondary | พื้นขาว ขอบ 1px blue-200 ตัว navy-700 | พื้น blue-50 | พื้น blue-100 | ตัว text-muted ความทึบ 0.6 |
| Ghost | โปร่งใส ตัว navy-700 | พื้น blue-50 | พื้น blue-100 | ความทึบ 0.5 |
| Danger | ขอบ 1px red-500 ตัว red-500 พื้นขาว | พื้น red-50 | พื้น red-500 ตัวขาว | ความทึบ 0.5 |
| Danger solid (ยืนยันลบ) | พื้น red-500 ตัวขาว | สว่างลง 8% | สว่างลง 14% | ความทึบ 0.5 |

- ไอคอนในปุ่ม 16 (sm/md) หรือ 18 (lg) ห่างข้อความ 8
- ปุ่มไอคอนอย่างเดียว: วงกลม 32 / 36 / 40 แบบ Ghost ต้องมี `aria-label`
- ในหนึ่งพื้นที่มีปุ่ม Primary ได้ 1 ปุ่ม; ปุ่มยืนยันอยู่ขวา ปุ่มยกเลิกอยู่ซ้ายของปุ่มยืนยัน ปุ่มลบอยู่ซ้ายสุดแยกจากกลุ่ม

### 7.2 ช่องกรอก
- บรรทัดเดียว: สูง 40 (หน้า auth 44), ทรงแคปซูล, padding 0 16, พื้นขาว, ขอบ 1px blue-200, ตัวอักษร `body`
- ป้ายชื่อช่องอยู่เหนือช่อง `caption` 12 น้ำหนัก 600 สี navy-900 ห่าง 6
- Hover: ขอบ blue-500 ความทึบ 60% · Focus: ขอบ blue-500 + วงแหวน `0 0 0 3px rgba(94,131,186,.25)` · Error: ขอบ red-500 + ข้อความใต้ช่อง 12 สี navy-900 นำหน้าด้วยไอคอนแดง · Disabled: พื้น blue-50
- Textarea: มน `--r-md`, padding 16; พื้นที่เขียนโน้ตพื้น parchment ไม่มีขอบ, ตัวอักษร 15/26
- ช่องรหัสผ่านมีปุ่มรูปตาแสดง/ซ่อนในช่องด้านขวา
- ช่องเงินชิดขวา ใช้ tabular-nums และมีหน่วย "THB" สี text-muted ในช่อง
- ช่องค้นหา: ไอคอนแว่นขยาย 16 ด้านซ้าย padding ซ้าย 40

### 7.3 การ์ดทั่วไป
- พื้นขาว, มน 16, ขอบ 1px `--line`, เงา `--shadow-sm`, padding 20 / 24
- หัวการ์ด: ป้าย `overline` สี text-muted → ตัวเลข `stat` → คำอธิบาย `body-sm`
- การ์ดที่คลิกได้ (การ์ดพอร์ต, การ์ดแผน): hover เงา `--shadow-md` และขอบ blue-200, เปลี่ยนแบบ 160ms, cursor pointer
- กล่องข้อความแนะนำ/หมายเหตุ: พื้น parchment, มน 12, padding 16, ไอคอนข้อมูล 18 สี navy-700

### 9.3 Hover / Focus / กด
| สถานะ | สเปก |
|---|---|

| Focus (คีย์บอร์ด) | เหมือน hover + วงแหวน 2px ขาวด้านในและ 2px blue-500 ด้านนอก |

| คลิก | เปิดหน้าแก้โน้ตนั้น |

## 14. แนวทางที่ใช้จริงในโค้ด (Tailwind, Motion, Component ร่วม)

หัวข้อนี้สรุปสิ่งที่ลงมือทำจริงตั้งแต่หน้า Onboarding / Login / Register เพื่อให้หน้าถัดไปใช้แนวเดียวกัน ถ้าไม่แน่ใจให้เปิดไฟล์อ้างอิงใน `frontend/src/onboarding/` เป็นตัวอย่าง

### 14.1 Tailwind และ token
- Token อยู่ใน `@theme` ของ `frontend/src/index.css` ใช้ผ่าน class เท่านั้น ไม่ใส่ hex/rgba ใน component
  - สี: `text-navy-900`, `bg-surface`, `bg-blue-500`, `border-blue-200`, `text-text-muted`, `bg-green-500` ฯลฯ (ชื่อตามหัวข้อ 2)
  - มุม: `rounded-pill` (999), `rounded-xl` (20), `rounded-lg` (16), `rounded-4xl` (32 ใช้กับการ์ด auth)
  - เงา: `shadow-sm|md|lg`, `shadow-cta` (เงาฟ้าใต้ปุ่มหลัก), `shadow-focus` (วงแหวนช่องกรอก)
  - Easing: `--ease-soft` (เข้าอย่างนุ่ม), `--ease-bounce` (เด้งเกินเป้าเล็กน้อย)
- ถ้าต้องมีสี/เงา/แอนิเมชันใหม่ **เพิ่ม token ใน `@theme` ก่อน** แล้วค่อยใช้ ห้ามใส่ตรงใน component
- ระยะห่างใช้ scale ของ Tailwind (1 หน่วย = 4px) เช่น `mt-6` = 24 ค่าตามภาพ Figma ที่ไม่ใช่ผลคูณของ 4 ให้ใช้ค่าที่ใกล้สุด ส่วนขนาดเฉพาะใช้ arbitrary value ได้ (`text-[26px]`, `w-[clamp(...)]`)
- ฟอนต์ติดไปกับแอปผ่าน `@fontsource/montserrat` และ `@fontsource/ibm-plex-sans-thai` (import ใน `index.css`) ไอคอนใช้ `lucide-react` (`strokeWidth={1.75}`, ไอคอนตกแต่งใส่ `aria-hidden="true"`)
- ข้อความยังเป็นอังกฤษตรงๆ เพราะยังไม่ได้ติดตั้งระบบแปลภาษา ต้องย้ายเข้าระบบแปลเมื่อติดตั้ง

### 14.2 เมื่อ Figma ไม่ตรงกับเอกสารนี้
- **ขนาด/ระยะ/เลย์เอาต์:** ยึด Figma (ตัวอย่าง: แบนเนอร์ Onboarding 436px, page padding 60, ปุ่มสูง 52 ตัวอักษร 20, หัวข้อ Login 44/32, การ์ด auth กว้าง 860, modal กว้าง 464)
- **สี:** ยึด palette ในหัวข้อ 2 (เช่นวงกลมเช็กใน modal ใช้ `green-500` ทั้งที่ Figma เขียวอ่อนกว่า) ถ้าต้องการสีใหม่ให้เพิ่ม token แล้วจดไว้ที่นี่
- **Placeholder ที่ Figma คัดลอกผิด** (เช่นทุกช่องเป็น your.email@example.com) ให้ใช้ข้อความที่สื่อความหมายจริง
- ถ้าตัดสินใจต่างจาก Figma หรือเอกสาร ให้บอกผู้ใช้ในสรุปงานเสมอ

### 14.3 การเปลี่ยนหน้า (Page transition)
แนวคิด: **แถบหัวอยู่นิ่ง เนื้อหาลอยเข้า–ลอยออก** ใช้ชุดเดียวกันทุกหน้าที่เปลี่ยนด้วยการกดปุ่ม

| ช่วง | แอนิเมชัน | ค่า |
|---|---|---|
| เข้าหน้า | `animate-fade-up` (จางเข้า + ลอยขึ้นจากล่าง 16px) | 450ms ease-soft เหลื่อมทีละส่วน `[animation-delay:80ms]` / `160ms` / `240ms` |
| ออกจากหน้า | `animate-page-out` (จางหาย + ลอยขึ้น 12px) | 250ms ease-in แล้วค่อยนำทาง |

ลำดับการเข้า (บนลงล่าง): ปุ่มสลับ/ปุ่มกลับ (0) → แบนเนอร์หรือหัวข้อ (80) → หัวข้อ/การ์ด (160) → ปุ่มหรือส่วนล่าง (240)

วิธีใช้ในหน้าใหม่ (ดู `login.tsx`, `onboarding-inconnected.tsx`):
```tsx
const { leaving, leaveTo } = usePageLeave()          // components/use-page-leave.ts
<div className={leaving ? 'animate-page-out motion-reduce:animate-none' : ''}> ...เนื้อหา... </div>
<button onClick={() => leaveTo(onBack)}>…</button>  // ห่อ callback นำทางทุกตัวด้วย leaveTo
```
- `leaveTo(cb)` ตั้ง `leaving` แล้วเรียก `cb` หลัง 250ms (ถ้าผู้ใช้ตั้ง reduce motion เรียกทันที) และกันกดซ้ำให้
- ผู้เรียกหน้า (ตอนนี้คือ `App.tsx`) เป็นคนเปลี่ยนหน้าจริงใน `cb` หน้าไม่นำทางเอง
- ปุ่มที่ไม่ได้เปลี่ยนหน้า (เช่น แสดง/ซ่อนรหัสผ่าน) ห้ามใช้ `leaveTo`
- `Opening → Onboarding` ก็ใช้แบบเดียวกัน: Splash เล่นจบ ค้างรวม 2.6 วินาที แล้ว `leaveTo` ออก ก่อนหน้า Onboarding ลอยเข้า (รวมไม่เกิน ~3 วินาทีตามสเปก)

### 14.4 Splash / Opening (`opening-page.tsx`)
| ช่วงเวลา | องค์ประกอบ | แอนิเมชัน |
|---|---|---|
| 0 – 1000ms | โลโก้วาฬ (สูง 160) | `animate-logo-in`: ขยาย .4 → 1.1 → .97 → 1 (เด้งหลังขยายเต็ม) |
| 1000 – 2000ms | "Whale Trade Journal" | `animate-title-bounce`: ตกลงมาแล้วเด้งกลับ (translateY -24 → 8 → -4 → 0) |

### 14.5 Modal (`modals/`)
- ใช้ `modal-frame.tsx` เป็นกรอบเสมอ: ฉากหลัง `bg-black/40` จางเข้า (`animate-scrim-in` 200ms), การ์ดเด้งขึ้น `animate-modal-pop` (600ms: 0.6 → 1.06 → .97 → 1 + ลอยขึ้น 24px), ปิดด้วย `animate-modal-out` 200ms (ย่อ .92 + จาง)
- Modal แจ้งสำเร็จใช้ `success-check.tsx`: วงกลมเด้ง `animate-circle-pop` (เริ่ม 250ms) แล้วเครื่องหมายถูกถูกวาดตาม `animate-check-draw` (เริ่ม 650ms ใช้ `pathLength={1}` + `stroke-dashoffset`)
- การ์ด: กว้างสูงสุด 464 (`max-w-116`), `rounded-3xl`, `px-12 py-10`, ขนาดวงกลมใช้ `clamp(...)` ตามความสูงหน้าต่าง
- พฤติกรรมที่ต้องมี: `role="dialog"` + `aria-modal` + `aria-labelledby/describedby`, กัก focus ในกล่อง (Tab วนในกล่อง), ปิดด้วย Esc, โฟกัสปุ่มที่มี `data-autofocus` ตอนเปิด
- Mount เฉพาะตอนเปิด (`open ? <Dialog/> : null`) เพื่อให้แอนิเมชันและตัวจับเวลาเริ่มใหม่ทุกครั้ง และหลีกเลี่ยง setState ใน effect
- ปิดแบบสองจังหวะ: ตั้ง `closing = true` → เล่นแอนิเมชันออก 200ms → ค่อยเรียก `onClose`
- Login Success: ปิดเองหลัง 2 วินาที / Register Success (รหัสกู้คืน): **ไม่ปิดเอง** ต้องกด OK หรือ Esc และมีปุ่ม copy (ไอคอนเปลี่ยนเป็นเครื่องหมายถูก 1.5 วินาที)

### 14.6 ปุ่ม: เคอร์เซอร์และความเด้ง (กฎส่วนกลางท้าย `index.css`)
- ทุก `button` / `[role=button]` / `a[href]` / `select` / `label[for]` / checkbox / radio เป็น `cursor: pointer`; ที่ disabled เป็น `not-allowed` (Tailwind preflight รีเซ็ตเป็นลูกศร จึงต้องมีกฎนี้)
- ปุ่มทุกปุ่ม **เด้งอัตโนมัติ** โดยไม่ต้องใส่ class: hover `scale 1.04`, กด `scale 0.94`, easing `--ease-bounce` 250ms; สี/เงาเปลี่ยนแบบ ease-out 150ms (ไม่เด้ง); ปุ่ม disabled ไม่เด้ง; ผู้ใช้ reduce motion ไม่เด้ง
- กฎนี้เขียน **นอก `@layer`** โดยตั้งใจ เพื่อให้ชนะ `transition-*` ของ utility ในปุ่มแต่ละปุ่ม และใช้ property `scale` (ไม่ใช่ `transform`) จึงไม่ชนกับ `-translate-*` หรือ keyframes ของ element เดียวกัน
- ตั้งใจ **ไม่รวม** ลิงก์ข้อความ และการ์ดใบใหญ่ที่คลิกได้ทั้งใบ (การ์ดโน้ต การ์ดพอร์ต) ซึ่งมี hover/กดของตัวเองในหัวข้อ 7.3 และ 9.3
- ปุ่มใหญ่ของ Onboarding/Auth ใช้ `components/onboarding-button.tsx` (Primary/Secondary, สูง 52, ตัวอักษร 20, `shadow-cta`)

### 14.7 ฟอร์ม (`components/auth-field.tsx`)
- ใช้ `TextField` / `PasswordField` (ป้ายชื่อ + ช่อง + ข้อความ error) และ `FieldError` ไม่เขียนช่องกรอกเองซ้ำ
- ช่อง: สูง 44 (หน้าต่างเตี้ย 40), ทรงแคปซูล, ขอบ 2px `blue-500`, error = ขอบ `red-500` + `FieldError` (ไอคอน `CircleAlert` แดง + ข้อความสี navy-900), focus = `shadow-focus`, `aria-invalid` และ `aria-describedby` ครบ
- `PasswordField` มีปุ่มตาแสดง/ซ่อน (`aria-label`) และรับ `labelAction` สำหรับลิงก์ข้างป้ายชื่อ (เช่น Forgot Password?)
- ตรวจข้อมูลตอนกด submit (ไม่ตรวจขณะพิมพ์), `noValidate` บน `<form>`, ข้อผิดพลาดจากระบบแสดงใต้ฟอร์มด้วย `role="alert"`
- ฟอร์มรับ callback จากภายนอก (`onLogin`, `onRegister` ที่ throw `Error` เมื่อล้มเหลว) หน้าไม่เรียก API เอง

### 14.8 Responsive ที่ใช้จริง
- ความกว้าง: `min-[1280px]:` เปลี่ยน page padding 32 → 60 และขนาดหัวข้อ, `min-[1100px]:` แสดง/ซ่อนส่วนภาพประกอบของการ์ด auth
- ความสูง: variant **`short`** (หน้าต่างสูง < 760 เช่น 1024 × 680) ประกาศใน `index.css` ด้วย `@custom-variant short` ใช้บีบหน้าที่ยาวให้พอดีจอ: ลดความสูงปุ่ม (52 → 48) ช่องกรอก (44 → 40) ระยะห่างหัวข้อ/ฟอร์ม และ padding บนของแถบหัว
- รูปภาพที่ควรย่อตามจอใช้ `clamp()` ผูกกับ `100vh` (เช่นแบนเนอร์ `w-[clamp(200px,calc(100vh_-_440px),436px)]`)
- ใช้ `min-h-screen` ไม่ใช้ความสูงตายตัว ให้หน้าเลื่อนแนวตั้งได้ถ้าเนื้อหายาวกว่าจอ แต่ห้ามเลื่อนแนวนอน
- ข้อความและปุ่มใช้ `min-w-*` แทนความกว้างตายตัว เพื่อเผื่อภาษาไทยยาวกว่า

### 14.10 ข้อควรระวังตอนทำหน้าใหม่
- ทุก `animate-*` ต้องมี `motion-reduce:animate-none` คู่กัน
- อย่าใส่ `transform` ลง element ที่มี keyframes ของตัวเอง ใช้ `scale` / `translate` utility ที่เป็น property แยกแทน
- ตรวจหน้าจริงด้วยภาพ: build แล้วถ่ายภาพด้วย Chrome headless (`--window-size=<กว้าง>,<สูง> --virtual-time-budget=<ms> --screenshot=...`) ที่ 1024 × 680 และ 1250 × 1110 เป็นอย่างน้อย หน้าที่เปลี่ยนหลังหน่วงเวลา (เช่นหลัง Opening) ต้องตั้ง budget สูงมาก (~15000) เพราะแอนิเมชัน CSS ไม่เดินตาม virtual time
- ปุ่มที่ต่อกับ backend ที่ยังไม่มี ให้เป็น prop callback (`onXxx?: () => void`) แล้วให้ `App.tsx` ต่อชั่วคราว
